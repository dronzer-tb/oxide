# Oxide Debug Plugin

Debug-only Folia plugin. Shows a player, in-game, whether the chunk they are
currently standing in was generated by Oxide (Rust) or vanilla Java.

**This is a diagnostic tool, not a production feature.** It is read-only: it
does no chunk routing, no player-radius pregen scheduling, and no
generation of any kind. That's milestone 5's hot-radius router (see
`docs/ROADMAP.md`), which this plugin has nothing to do with beyond sharing
a codebase location.

## Why the action bar, not the F3 debug screen

The F3 debug screen is rendered entirely client-side by the Minecraft
client. There is no server API or packet that lets a server add, replace,
or append a line to it — it isn't an extension point, it's baked into the
client jar. Any plugin claiming to "add an F3 line" is either lying or
depending on a client mod.

The action bar (the text that floats above the hotbar) *is* a real,
documented server→client message (`sendActionBar`), works on vanilla Java
clients, and passes through to Bedrock clients via Geyser with no client
mod required on either side. That's why this plugin uses it.

## Setup: the Folia API version

`plugin/gradle.properties` pins `foliaApiVersion=26.2.build.5-beta`, confirmed
against `dev.folia:folia-api`'s `maven-metadata.xml` on 2026-08-22 — still a
beta upstream. Re-check that metadata if a stable 26.2 release lands. It
requires JVM 25+, which is why `javaVersion=25`.

The Minecraft/`api-version` value in `paper-plugin.yml` is a separate
property, `mcApiVersion`, substituted at build time via `processResources`.

## Commands & permissions

- `/oxide debug on|off` — toggle the action-bar overlay for yourself. Off by
  default.
- `/oxide here` — one-shot chat dump for your current chunk: chunk
  coordinates, region file name, whether a sidecar file was found, and the
  raw bit value.

Both require permission `oxide.debug` (default: `op`).

- `/oxide createworld <name> [seed]` — creates a new world generated by the
  real Rust generator over `oxide-ffi`. Requires `oxide.createworld`
  (default: `op`); usable from console/RCON as well as in-game. Terrain is
  noise-shaped solid/fluid/air **only** — no surface rules, no biome blocks,
  no caves, no structures, no bedrock. See `OxideChunkGenerator`'s class doc.

`createworld` is the clean path: a fresh world, generated by Oxide from its
first chunk. Without the `bukkit.yml` opt-in below, every other world on the
server — including the default one — stays vanilla.

Commands are registered through Paper's `LifecycleEvents.COMMANDS` registrar;
the `commands:` block in `paper-plugin.yml` is descriptor metadata only and
does not wire execution on its own.

## Pointing an existing world at the generator

Opt in per world in `bukkit.yml`, then restart:

```yaml
worlds:
  world:
    generator: OxideDebug        # or OxideDebug:12345 to choose the seed
```

Read this before doing it to a world you care about:

- **Existing chunks never change.** A world's generated chunks live on disk and
  are never re-run through a generator. Everything already explored stays as
  vanilla wrote it; only chunks generated from that point on come from Oxide.
- **Old and new terrain will not line up.** Where a new Oxide chunk meets an old
  vanilla one you get a hard seam — the two disagree about terrain shape.
- **What you get is not a playable world.** Noise-shaped stone/water/air only:
  no surface blocks, no ores, no caves, no structures, no bedrock, no biome
  variation.

There is no in-place "regenerate this world with Oxide". That would mean
deleting the world's region files, which this plugin will not do for you.

## Where the data comes from

Oxide writes a sidecar file next to each `.mca` region file it touches:
`<world>/region/r.<regionX>.<regionZ>.mca.oxide` — a 136-byte bitmap, one
bit per chunk in that region, set if Oxide generated that chunk. This
plugin only reads that file; it never writes it.

**This can drift from reality.** If a world is copied, merged, restored
from a backup, or hand-edited by an external tool (MCEdit, WorldEdit
schematics pasted across region boundaries, a datapack regen, etc.) without
also carrying the matching `.oxide` sidecars, the bitmap will report stale
or wrong provenance for the affected chunks. Treat this readout as "what
Oxide believes it wrote", not as ground truth independently re-derived from
the chunk's actual contents.

A missing sidecar file is normal (regions with no Oxide-generated chunks
won't have one) and reports as `chunkgen: java`. A sidecar file that exists
but fails to parse (bad magic, unknown version, wrong length) is logged
once and reports as `chunkgen: unknown` — it is never silently reported as
`java`, because a wrong answer here is worse than an admitted "don't know".

## Folia threading

This plugin never calls `Bukkit.getScheduler()`. All work that touches a
specific `Player` runs through that player's entity scheduler
(`player.getScheduler()`), which Folia guarantees executes on the region
thread currently owning that player. See the javadoc on `ChunkTracker` and
`OxideCommand` for the per-call-site reasoning. Getting this wrong on Folia
produces intermittent region-thread-safety crashes rather than a clean
failure, so scheduler choice is treated as load-bearing, not incidental.

## Building

Do not run a Gradle build locally for this module — heavy/verifying builds
for this project run in GitHub Actions (`.github/workflows/plugin.yml`, Java
25 toolchain). That workflow builds the Rust cdylib first and then the jar,
so the two are always built from the same commit:

```
cargo build --release -p oxide-ffi     # -> target/release/liboxide_ffi.so
cd plugin && gradle build              # embeds it at natives/linux-x86_64/
```

`processResources` picks the `.so` up from `target/release/` by default;
override with `-PnativeLibraryFile=/abs/path`. A missing library only warns —
the resulting jar still runs the provenance overlay, and only
`/oxide createworld` fails on it.

## Installing

Download the jar straight from the rolling release -- no zip, no artifact
extraction, and the link stays valid across builds:

```sh
gh release download latest --repo dronzer-tb/oxide -p OxideDebug.jar
```

`gh` rather than `curl` because this repo is private: release assets 404 for
unauthenticated requests. While it stays private, a plain download needs a token:

```sh
curl -L -H "Authorization: Bearer $GITHUB_TOKEN" -H "Accept: application/octet-stream" \
  "$(gh api repos/dronzer-tb/oxide/releases/tags/latest -q '.assets[]|select(.name=="OxideDebug.jar").url')"
```

If the repo is ever made public, this becomes a plain link with no auth at all:
`https://github.com/dronzer-tb/oxide/releases/latest/download/OxideDebug.jar`

Every push to `main` replaces it (`.github/workflows/plugin.yml`). The same
release also carries a bare `liboxide_ffi.so`, needed only for the
`native-library-path` override below -- the jar already embeds its own copy,
built from the same commit.

Drop the jar in `plugins/`. On the first `/oxide createworld`, the embedded
linux-x86_64 library is extracted to `plugins/OxideDebug/liboxide_ffi.so` and
loaded from there (Panama's `SymbolLookup.libraryLookup` needs a real
filesystem path; it cannot dlopen a jar entry). Extraction overwrites on every
server start, so a jar upgrade never keeps loading a stale library.

Set `native-library-path` in `config.yml` to an existing `.so` to override the
embedded one; leave it empty otherwise. `datapack-path` must point at an
extracted vanilla worldgen datapack — see `docs/REFERENCE_DATA.md`.

The server JVM needs `--enable-native-access=ALL-UNNAMED`; JDK 25 only warns
without it today, but a later JDK blocks the downcalls outright.

## Tests

`src/test/java` has JUnit 5 unit tests for the parts of this plugin that
don't need a running server: sidecar parsing (valid / missing / bad magic /
truncated), the sidecar cache's mtime-invalidation behaviour, and the
region-coordinate / bit-index math (including negative chunk coordinates).
They are wired into Gradle (`tasks.test { useJUnitPlatform() }`) but, per
the same no-local-build rule, are meant to run in CI, not on this machine.
