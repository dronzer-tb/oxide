# Oxide Debug Plugin

Debug-only Folia plugin. Shows a player, in-game, whether the chunk they are
currently standing in was generated by Oxide (Rust) or vanilla Java.

**This is a diagnostic tool, not a production feature.** It is read-only: it
does no chunk routing, no player-radius pregen scheduling, and no
generation of any kind. That's milestone 5's hot-radius router (see
`docs/ROADMAP.md`), which this plugin has nothing to do with beyond sharing
a codebase location.

## Why the action bar, not the F3 debug screen

The F3 debug screen is rendered entirely client-side by the Minecraft
client. There is no server API or packet that lets a server add, replace,
or append a line to it — it isn't an extension point, it's baked into the
client jar. Any plugin claiming to "add an F3 line" is either lying or
depending on a client mod.

The action bar (the text that floats above the hotbar) *is* a real,
documented server→client message (`sendActionBar`), works on vanilla Java
clients, and passes through to Bedrock clients via Geyser with no client
mod required on either side. That's why this plugin uses it.

## Setup: the Folia API version

No one has confirmed which Folia build targets Minecraft 26.2 yet (26.2 is
the version this whole Oxide project is pinned to — see
`docs/ARCHITECTURE.md`). `plugin/gradle.properties` has a placeholder:

```properties
foliaApiVersion=UNCONFIRMED-SET-ME-TO-REAL-26.2-FOLIA-API-VERSION
```

This build will not resolve until that's replaced with a real, verified
`dev.folia:folia-api` version for 26.2. Check
`https://repo.papermc.io/service/rest/repository/browse/maven-public/dev/folia/folia-api/`
or `https://papermc.io/downloads/folia` before setting it — do not guess.

The Minecraft/`api-version` value in `paper-plugin.yml` is a separate
property, `mcApiVersion`, substituted at build time via `processResources`.

## Commands & permissions

- `/oxide debug on|off` — toggle the action-bar overlay for yourself. Off by
  default.
- `/oxide here` — one-shot chat dump for your current chunk: chunk
  coordinates, region file name, whether a sidecar file was found, and the
  raw bit value.

Both require permission `oxide.debug` (default: `op`).

## Where the data comes from

Oxide writes a sidecar file next to each `.mca` region file it touches:
`<world>/region/r.<regionX>.<regionZ>.mca.oxide` — a 136-byte bitmap, one
bit per chunk in that region, set if Oxide generated that chunk. This
plugin only reads that file; it never writes it.

**This can drift from reality.** If a world is copied, merged, restored
from a backup, or hand-edited by an external tool (MCEdit, WorldEdit
schematics pasted across region boundaries, a datapack regen, etc.) without
also carrying the matching `.oxide` sidecars, the bitmap will report stale
or wrong provenance for the affected chunks. Treat this readout as "what
Oxide believes it wrote", not as ground truth independently re-derived from
the chunk's actual contents.

A missing sidecar file is normal (regions with no Oxide-generated chunks
won't have one) and reports as `chunkgen: java`. A sidecar file that exists
but fails to parse (bad magic, unknown version, wrong length) is logged
once and reports as `chunkgen: unknown` — it is never silently reported as
`java`, because a wrong answer here is worse than an admitted "don't know".

## Folia threading

This plugin never calls `Bukkit.getScheduler()`. All work that touches a
specific `Player` runs through that player's entity scheduler
(`player.getScheduler()`), which Folia guarantees executes on the region
thread currently owning that player. See the javadoc on `ChunkTracker` and
`OxideCommand` for the per-call-site reasoning. Getting this wrong on Folia
produces intermittent region-thread-safety crashes rather than a clean
failure, so scheduler choice is treated as load-bearing, not incidental.

## Building

Do not run a Gradle build locally for this module — heavy/verifying builds
for this project run in GitHub Actions. This directory's build files are
meant to be picked up by a CI workflow (`./gradlew build` with a Java 21
toolchain) once `foliaApiVersion` above is filled in with a real version.

## Tests

`src/test/java` has JUnit 5 unit tests for the parts of this plugin that
don't need a running server: sidecar parsing (valid / missing / bad magic /
truncated), the sidecar cache's mtime-invalidation behaviour, and the
region-coordinate / bit-index math (including negative chunk coordinates).
They are wired into Gradle (`tasks.test { useJUnitPlatform() }`) but, per
the same no-local-build rule, are meant to run in CI, not on this machine.
